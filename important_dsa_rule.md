Using videos (like Raj Vikramaditya (Striver)) to understand the **approach**, then coding it yourself is **not wrong**. In fact, many beginners learn this way. But if this becomes your *main/default method*, it creates hidden weaknesses.

## Short Answer

It is a **good learning tool**, but a **bad long-term solving strategy** if overused.

You should use videos to **learn patterns**, not to replace your own thinking process.

---

# Why It Feels Good Right Now

When you watch solution videos:

* You quickly understand optimized logic.
* You save time.
* You feel productive because you can code it after.
* You learn standard patterns (two pointers, sliding window, DP, graphs).

That’s useful.

---

# Problems You May Face in Future

## 1. Weak Problem-Solving Muscle

DSA is not coding only. It is:

1. Read problem
2. Analyze constraints
3. Find pattern
4. Create logic
5. Handle edge cases
6. Then code

If you directly consume the approach, you skip steps 2–5.

Later in interviews or contests, when no one explains the pattern, you may freeze.

---

## 2. Illusion of Understanding

Watching someone solve feels like *you know it*.

But when a similar problem appears with a twist:

* different constraints
* modified condition
* unusual edge case

You may get stuck.

Because recognition ≠ creation.

---

## 3. Dependency on Hints

Your brain gets trained to think:

> “Let me see solution first.”

That habit is dangerous in placements/interviews.

---

## 4. Poor Pattern Detection Speed

Real strong candidates see:

* HashMap needed
* Binary Search on answer
* Greedy works
* DFS/BFS graph model

This comes from struggling with problems yourself first.

---

# Best Way to Use Videos (Smart Method)

## Gold Formula

### Step 1: Try Problem Alone First (20–40 mins)

Think seriously.

* Brute force?
* Better approach?
* Data structure?
* Constraints?

Even if stuck, this struggle builds brainpower.

---

### Step 2: Take Hint, Not Full Solution

Watch only enough to know direction.

Example:

* “Use sliding window”
* “Think prefix sum”
* “Use monotonic stack”

Pause video.

Try again yourself.

---

### Step 3: Code Fully Yourself

No copy-paste.

Write from memory.

Debug it.

---

### Step 4: Revisit After 2–3 Days

Solve same problem without notes.

Then pattern becomes yours.

---

# What Top Learners Do

They don’t watch 1000 solutions.

They deeply solve 200–300 problems.

---

# Real Example

If you watch 20 DP videos:

You may know formulas.

But if interviewer asks custom DP state design, you struggle.

If you fought through 8 DP problems yourself:

You can build new states.

That is real skill.

# What You Should Do From Today

Since you are serious about growth:

## For each problem:

* 30 min own attempt
* 10 min hints/video
* Solve yourself
* Write notes: “Pattern learned”
* Re-solve later
